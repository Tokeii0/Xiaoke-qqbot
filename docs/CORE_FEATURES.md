# 核心功能与实现

本文描述仓库中已经实现的行为。示例对话为虚构，展示的是预期路径；模型判断有不确定性，不保证每次逐字回复。

## JEV 负责判断，程序负责执行

对话模型组织语言，TypeSafe JEV 返回结构化语义判断。程序结合权限、阈值、时间、状态和发送结果决定是否执行。JEV 不直接执行任意代码，也不能绕过群白名单或管理员权限。

| 判断 | 影响的行为 |
| --- | --- |
| 是否在叫机器人、是否值得参与、打扰程度、兴趣相关性 | 是否加入本轮群聊；无人点名的发言可受主动预算约束 |
| 场景、情绪指向、话题是否延续 | 采用讲解、安慰、玩笑、庆祝等表达，或在话题结束时收口 |
| 回复深度 | 区分简短接话、普通回应和需要展开的回答 |
| 长期价值、纠正对象、问题状态 | 保存或修正本地事实，记录未解决事项，选择相关追问 |
| 知识价值、相关性与有效性 | 保存已确认解决方案，回答同类问题时引用来源 |
| 工具意图、偏好适用范围 | 创建或取消提醒、整理事项、应用个人或群级回复偏好 |
| 搜索、语音、生活配图、手误是否合适 | 选择呈现形式或附加步骤 |

入口在 [`judge.py`](../xiaoke_bot/judge.py)，编排在 [`plugin.py`](../xiaoke_bot/plugin.py)。各功能判断可分别启用，不能把它理解为“一条消息永远只请求一次 JEV”。

## 自然接话与适时结束

“你是不是在摸鱼？”这类轻松打趣，可以只回“你猜”。系统按语义选择回复深度，在适合短答时减少无关日程背景和额外追问，并检查多余的尾句。

短回复整理只保留原回复中语义完整的前缀。例如“可以，但语音还没配置好”的限制不能被删掉。判断失败或不确定时保留原文；认真求助、必要事实、条件和否定优先于简短。

分段发送使用随字数变化的间隔。手误模拟另有概率与会话冷却，只在 JEV 认可的轻松闲聊里低频触发，避免改坏代码、网址、数字或严肃回复。

主要实现：[`semantic.py`](../xiaoke_bot/semantic.py)、[`prompts.py`](../xiaoke_bot/prompts.py)、[`humanize.py`](../xiaoke_bot/humanize.py)、[`typing_style.py`](../xiaoke_bot/typing_style.py)。

## 记忆、知识与自然语言纠错

记忆分为几层，各有不同用途：

| 层次 | 用途 |
| --- | --- |
| 短期聊天历史 | 恢复近期上下文、说话者及图片信息 |
| TencentDB Agent Memory | 对话采集、长期提取和检索召回 |
| 本地确认事实与偏好 | 记录明确的本人信息，处理改口和回复偏好 |
| 群知识 | 保存问题、确认的解决方案和源消息 |
| 未解决事项 | 记录待跟进问题以及是否已经追问 |

例如，“我现在改用 Linux 了”可以修正旧事实；“刚才是在开玩笑，别记住”会定位并撤回可纠正的本地事实。群内问题得到确认解决后，可以整理成知识条目，再次引用时附来源。

“以后代码问题用文字回答”作为回复偏好处理。普通成员可以修改自己的偏好；要改变整个群的偏好，需要群管理或超管权限。知识和本地记录按会话范围检索，纠正时还会检查记录归属。

**撤回本地事实不等于擦除所有副本。** 历史聊天、请求日志、备份及网关已采集内容可能仍然存在。网关管理检索和跨会话范围的限制见[配置指南](CONFIGURATION.md#记忆与数据范围)。

主要实现：[`history.py`](../xiaoke_bot/history.py)、[`clients.py`](../xiaoke_bot/clients.py)、[`intelligence.py`](../xiaoke_bot/intelligence.py)、[`intelligence_store.py`](../xiaoke_bot/intelligence_store.py)、[`learning.py`](../xiaoke_bot/learning.py)。

## 事项跟进与一次性提醒

“昨天部署失败”的事项可以保持未完成状态；当同一成员再次谈到相关话题、且满足最短间隔时，JEV 判断是否适合追问。已解决或已经问过的事项会减少重复打扰。这是依托当前对话的跟进机制。

提醒由 JEV 选择意图，随后用确定性规则解析时间和参数：

```text
小可，明早九点提醒我更新证书
小可，半小时后提醒我看看构建结果
小可，查看我的提醒
小可，取消提醒 12
小可，整理一下今天还没解决的问题
```

支持未来一年内、时间明确的一次性提醒。过去时间、重复任务、缺少内容或有歧义的表达会要求重写。到期发送前重新检查会话权限；机器人需要持续运行并保持连接。发送失败、权限阻止及逾期都有记录，不承诺可靠的关键告警投递。

主要实现：[`reminders.py`](../xiaoke_bot/reminders.py)、[`intelligence.py`](../xiaoke_bot/intelligence.py)。

## 校园日常与一致的生活细节

后台可编辑工作日 / 周末日程，并选择固定、自然变化或丰富变化模式。每日安排结合配置时区、日期、主题、时间浮动和短时事件生成；同一天可以稳定引用，次日会更新。

日程进入某个活动时，日常记录会补充并保存细节。例如早餐吃了什么、正在做什么。之后的对话优先使用已记录内容，不应随每次问答重新编造一份。

- **睡觉静默**：普通聊天与相关发送路径会检查睡眠状态。管理命令、审核和到期提醒等独立任务有各自流程，睡眠不等于停止所有后台任务。
- **强制起床**：后台输入理由，记录一次起床事件并解除当前连续睡眠；后续仍按日程活动，不会永久取消之后的睡眠。
- **日常配图**：结合已保存事件、场景、时间和校园设定生成第一人称 AI 配图。默认拍眼前的物品、环境和活动，不拍角色本人。
- **原图复用**：同一条日常记录保存标准图片；再次询问同一事件时复用原图，并发请求也避免为同一事件生成不同版本。

“小可今早吃什么？”可以触发相关记录选择和配图判断。开启照片功能不代表每次都发图；还取决于 JEV 阈值、事件是否适合、冷却和图片服务状态。

主要实现：[`routine.py`](../xiaoke_bot/routine.py)、[`routine_diary.py`](../xiaoke_bot/routine_diary.py)、[`campus_photo.py`](../xiaoke_bot/campus_photo.py)。

## 图片、语音和搜索

### 图片直接参与上下文

在直接模式下，图片作为多模态消息内容传给主对话模型，文本与图片保持在同一段对话里。主模型及备用模型都需要支持视觉输入。独立模式则先由识图模型提供描述，适用于纯文本主模型。图片数量、近期图片上限和表情包过滤可配置。

### QQ 语音

程序把已生成的回复正文交给语音服务，JEV 可以分别判断“适不适合语音”和“本轮怎么说”。基础音色保持稳定，在自然、甜美、温柔、轻快和认真等风格之间调整。文字偏好会影响语音选择。

机器人能感知语音是否配置及本轮发送方式；不会在正文中插入“🎙️ AI 合成语音”标签。生成超时或 QQ 发送失败时回退文字。音色与自然程度取决于所用服务，当前实现不包含声音克隆，也不是接收麦克风输入的实时通话。

### 联网搜索

JEV 判断是否需要新信息，Tavily 返回检索结果，再由当前对话模型整理并附来源。未配置、请求失败和没有结果会分别处理，不把模型已有知识说成刚刚检索得到的证据。

主要实现：[`vision.py`](../xiaoke_bot/vision.py)、[`voice.py`](../xiaoke_bot/voice.py)、[`web_search.py`](../xiaoke_bot/web_search.py)。

## 管理后台与运行记录

后台集中配置模型、人设、JEV、语音、日程、搜索和群管理功能。记忆、事项、提醒、知识和偏好用五个标签页展示，支持筛选、分页和详情查看。

统一请求日志记录本项目接入的模型调用，包括输入输出、功能标签、耗时、失败原因和可用的用量；JEV 记录同时呈现分数与阈值。独立记忆网关的内部调用仍由网关自身记录，不能把后台日志当作所有外部服务的完整账单。

额外管理能力包括成员互动画像、情绪与好感度、关键词审核、冒犯标记、聊天总结、Webhook 转发和可选入群名单审核。禁言、踢出等操作仍需要相应 QQ 权限。

主要实现：[`web_admin.py`](../xiaoke_bot/web_admin.py)、[`request_log.py`](../xiaoke_bot/request_log.py)、[`member_analysis.py`](../xiaoke_bot/member_analysis.py)、[`daily_summary.py`](../xiaoke_bot/daily_summary.py)。
